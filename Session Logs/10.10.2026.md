## Plumbing 2: P7

### Session Note: the import script and the search-terms fix (10.10, before P7, uncommitted)
- New `engine/import-pack.mjs`, script `import:pack` (one line added to `package.json`): `pnpm import:pack <investigation> [--skip-live] [--engine <url>] [--no-extract]`. Works only over the engine's HTTP routes through `src/data/` (engine-api sections 2.5 to 2.8). It creates the starting folders at the top level (reusing one of the same name), then imports every file in `data/<investigation>/sources/` into its folder with its register (sent as `system`, so `register` equals it), stored without the model (`extract: false`). With the model on it then reads the files one at a time, each waiting for the last (`POST extract`, then polling `health.extracting`), printing seconds and the final status per file; with the model off, or `--no-extract`, files are only stored. `--skip-live` leaves out the file imported on stage (`firearms-identification-report.pdf`, `hauling-contracts.pdf`); the live file's folder (Forensics, Procurement) is still created. A file the investigation already holds (same original name) is skipped, so a second run picks up where the first stopped, and running again without `--skip-live` imports only the live file. `--engine` defaults to `BARGHEST_ENGINE_URL` or `http://localhost:8787`. The folder, file and register table is `PACKS` in the script, from the P7 handoff. For Plumbing 1: please add this to `docs/engine-api.md`; Plumbing 2 does not edit the docs.
- Why one file at a time: every `import` with the model on starts its own extraction at once and `engine/llm.mjs` has no queue, so importing a pack through the plain route would put about two dozen files on Ollama together, each request waiting behind the others.
- `engine/ask/index.mjs` (the search-terms fix Builder 4 flagged): `person`, `incident`, `hauler`, `lgu`, `lgus`, `inspection` and `inspections` are no longer ignored words. (1) The keyword search matches a word by its stem at the start of a word, with accents ignored on both sides: "hauler" finds "Hauling", "inspections" finds "inspection", "pena" finds "Peña" (before this, a passage with "Peña" never matched the question's "pena"). (2) A word naming an object type (its name, display name or plural: "incident", "hauler", "LGUs", "school") brings in that type's objects, the most linked first, up to three per type, marked `byType` after the objects named by title or id. (3) The path the answer is built on now runs from the best named object to the best object of the type the question names, so "what connects Joaquin Dela Peña to the incident" connects him to the Incident instead of to another Dela Peña. (4) The keyword results take each file's best passage before any file's second, so five trip log rows or three blotter passages no longer crowd out the other files. (5) The Assistant's search hands the model 10 passages, the number the model reads (`ASK_PASSAGES`); the `GET search` route still defaults to 8. The reply shape is unchanged except the new `byType` flag on objects.
